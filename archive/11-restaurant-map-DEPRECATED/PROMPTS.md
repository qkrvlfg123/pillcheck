# 11 맛집 지도 — Claude Code 프롬프트 가이드

지도 + 필터링이 결합된 모듈이라 단계가 좀 됩니다. 지도 먼저 띄우고 →
데이터 연결 → 필터링 순서로.

---

## 0단계 · 준비

- 카카오 개발자(https://developers.kakao.com) 앱 생성 → REST API 키 + JavaScript 키
- 카카오맵 사용 등록(플랫폼에 사이트 도메인 등록 필요)
- 키는 `.env`에 저장, git 금지

## 1단계 · 지도 + 맛집 검색

```
카카오맵으로 맛집 검색 페이지를 만들어줘.
- 검색창에 "강남역 맛집" 같이 입력하면 카카오 로컬 API로 검색
- 결과를 지도에 마커로 표시 + 옆에 목록(이름, 카테고리, 거리)
- 마커 클릭하면 식당 이름·카카오맵 링크
카카오 JavaScript 키는 .env에서 읽고, REST 호출은 백엔드(또는 프록시)로.
먼저 구조 계획 말해주고 확인받아.
```

## 2단계 · 프로필 입력

```
사용자 프로필 입력 UI를 추가해줘.
- 질환 선택(체크박스): 역류성식도염, 위염, 불면, 통풍전단계, 대사증후군,
  고혈압, 당뇨 등 (../../packages/shared/data 참고)
- 복용약 입력(선택)
- 로그인 없이 이번 세션만 사용 가능하게(개인정보 최소)
```

## 3단계 · 카테고리 매핑 (이 모듈의 핵심)

```
카카오가 주는 식당 카테고리(예: "음식점 > 한식 > 국밥",
"음식점 > 일식 > 돈까스")를 우리 질환-음식 규칙과 연결하는
매핑 테이블을 만들어줘.
- ../../packages/shared/data 의 질환-음식 규칙에는 푸드코트 키워드와
  food_tag가 있어(국물, 튀김, 매운, 가당음료 등)
- 카카오 카테고리 문자열에서 이 키워드를 추출해 매칭
- 예: "돈까스"→FRIED, "국밥"→SOUP, "마라"→매운
매칭 결과를 packages/shared 형식과 맞춰줘.
```

## 4단계 · 필터링 + 경고 표시

```
프로필과 매핑을 이용해 검색된 맛집에 경고·추천을 표시해줘.
- 사용자 질환 규칙에 걸리는 카테고리면 마커·목록에 주의 표시(노랑/빨강)
- "이 집은 [질환]에 [이유]로 자극적일 수 있어요" 문구
- 걸리는 규칙 없는 집은 "무난해요" 표시
- 복용약이 있으면 약-음식 규칙도 함께 확인
  (예: 와파린 복용 + 녹색채소 많은 집 → 주의)
톤은 "먹지 마세요"가 아니라 "참고하세요".
```

## 5단계 · 약물 상호작용 연계 (선택 — 플랫폼 통합)

```
프로필에 복용약이 2개 이상이면,
../../packages/shared/engine/drug_interaction.py 의
check_interactions()로 약끼리 충돌도 함께 점검해서 상단에 알려줘.
(맛집과 별개로, 복용약 자체의 위험 조합 안내)
```

## 6단계 · 마무리

```
접근성·반응형 점검하고 실행법을 README에 정리해줘.
"참고용 안내, 진단 아님" 고지를 화면에 넣어줘.
카카오맵 저작권 표시(로고·출처)를 규정대로 넣었는지 확인해줘.
```

---

## 주의

- **카카오맵 API 이용약관** 준수: 카카오맵 데이터를 표시할 때 출처·로고 표기
  규정이 있음. 6단계에서 확인.
- 카카오맵에 있는 장소가 API에선 안 나오는 경우가 있음(한계). 검색 실패
  시 안내 문구 처리.
- 식당 "카테고리"만으로는 실제 메뉴를 다 알 수 없음. "이 카테고리는 보통
  이런 경향" 수준의 참고임을 명시.
- API 키(REST/JS)는 .env, git 금지. JS 키는 도메인 제한 걸기.
