# 10 챗봇 — Claude Code 프롬프트 가이드

RAG 챗봇은 부분이 많으니 순서대로 천천히 가세요. 책의 리뷰 RAG를 먼저
완성하고, 그 위에 약물 상담을 얹는 순서를 추천합니다.

---

## 0단계 · 준비

- Pinecone 계정(https://pinecone.io) + API 키
- 임베딩·LLM용 API 키 (OpenAI 또는 Anthropic)
- `.env`에 키 저장 (git 올리지 말 것)

## 1단계 · FastAPI 뼈대

```
이 폴더에 FastAPI 백엔드 뼈대를 만들어줘.
- /health : 상태 확인
- /chat : 질문을 받아 답변을 반환 (지금은 더미 응답)
- 먼저 폴더 구조와 설치 패키지 계획을 말해주고, 확인하면 진행해
```

## 2단계 · 임베딩 + Pinecone 연결

```
텍스트를 임베딩해서 Pinecone에 저장하고 검색하는 모듈을 만들어줘.
- upsert_documents(docs): 문서를 임베딩해 Pinecone에 저장
- search(query, top_k): 질문과 가장 비슷한 문서 top_k개 반환
- 임베딩 모델과 Pinecone 인덱스 설정은 .env에서 읽게
연결 테스트용 스크립트도 같이.
```

## 3단계 · 리뷰 데이터 넣기 (책의 기본 주제)

```
샘플 쇼핑 리뷰 데이터(상품별 리뷰 여러 개)를 만들고,
2단계 모듈로 Pinecone에 넣어줘.
고령자 관련 상품(혈압계, 돋보기, 미끄럼방지 슬리퍼 등)으로 리뷰를 구성해줘.
```

## 4단계 · RAG 파이프라인

```
랭체인으로 RAG 파이프라인을 만들어줘.
- 질문이 오면 Pinecone에서 관련 리뷰를 검색
- 검색된 리뷰를 근거로 LLM이 답변 생성
- 답변에 "어떤 리뷰를 근거로 했는지"를 함께 표시
/chat 엔드포인트에 연결해줘.
```

## 5단계 · 약물 상담 붙이기 (플랫폼 확장 — 핵심)

```
../../packages/shared/engine/drug_interaction.py 에 check(drug_list) 함수가 있어.
이건 식약처 DUR API를 우선 조회하고, 키가 없으면 데모 데이터로 폴백하되
'미검증'임을 표시하는 구조야.

/drug-check 엔드포인트를 새로 만들어줘.
- 사용자가 약 이름 목록을 보내면 (예: ["와파린", "부루펜"])
- check()로 조회하고
- 결과의 mode(DUR_OFFICIAL / DEMO_UNVERIFIED)를 사용자에게 그대로 표시
  · DUR 공식이면 "식약처 DUR 기준" 이라고 명시
  · 데모면 "미검증 참고 정보, 약사 확인 필요" 라고 명시
- 절대 챗봇이 임의로 "먹어도 된다/안 된다"를 단정하지 말 것
그리고 /chat에서 "이 약들 같이 먹어도 돼?" 류 질문을 이 엔드포인트로 라우팅.
```

DUR 서비스키는 `docs`나 shared/README의 안내대로 발급받아 `.env`에 넣으세요.

## 6단계 · 간단한 프런트 (선택)

```
이 챗봇을 테스트할 간단한 웹 채팅 화면을 만들어줘.
- 질문 입력창 + 대화 표시
- 고령자 대상이라 글씨·버튼 크게
- 약 상담일 때는 위험도를 색으로(빨강/노랑) 눈에 띄게
```

## 7단계 · 마무리

```
전체가 동작하는지 점검하고, 실행 방법을 README에 정리해줘.
"의료기기 아님, 참고용" 고지를 응답과 화면에 넣어줘.
```

---

## 주의

- **약물 상담은 참고용**임을 반드시 명시. 챗봇이 "먹어도 된다/안 된다"를
  단정하지 말고 "주의가 필요하다, 약사와 상의하라"는 톤으로.
- API 키는 전부 `.env`, git 금지.
- 5단계가 이 플랫폼의 하이라이트입니다. 여기서 데이터셋이 실제로 동작합니다.
