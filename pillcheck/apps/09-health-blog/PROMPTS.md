# 09 블로그 — Claude Code 프롬프트 가이드

이미 Next.js + Supabase로 시작한 상태라면, 현재 코드를 Claude Code에게
먼저 파악시키고 이어가세요.

---

## 0단계 · 준비

1. Supabase 프로젝트를 만들고(https://supabase.com) URL·anon key를 확보.
2. `.env.local`에 키를 넣습니다(이 파일은 절대 git에 올리지 말 것 — .gitignore 확인).

```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
```

## 1단계 · 현재 상태 파악 (이미 시작한 경우)

```
이 폴더는 Next.js + Supabase로 만들던 블로그야.
먼저 현재 코드 구조와 어디까지 됐는지 파악해서 정리해줘.
지금 동작하는 것과 빠진 것을 목록으로 알려줘. 코드는 아직 고치지 마.
```

## 2단계 · DB 스키마 설계

```
Supabase에 블로그 테이블을 설계해줘.
- posts: id, title, content, author_id, created_at, likes_count
- likes: id, post_id, user_id (중복 좋아요 방지)
- 고령자 건강정보 블로그라는 성격에 맞게 필요한 컬럼이 더 있으면 제안해줘
SQL 마이그레이션 파일로 만들어주고, Supabase 대시보드에서 실행하는 법도 알려줘.
```

## 3단계 · RLS 정책 (이 챕터의 핵심)

```
방금 만든 테이블에 RLS(Row Level Security) 정책을 걸어줘.
- posts: 누구나 읽기 가능, 작성은 로그인 사용자만,
  수정·삭제는 author_id가 본인일 때만
- likes: 로그인 사용자만 추가, 본인 좋아요만 취소 가능
각 정책이 왜 필요한지 한 줄씩 설명도 같이 적어줘.
정책 없이 두면 어떤 공격이 가능한지도 알려줘.
```

## 4단계 · 글 목록 / 상세 / 작성

```
블로그 화면을 만들어줘.
- 홈: 글 목록 (제목, 작성일, 좋아요 수)
- 상세: 글 전문 + 좋아요 버튼
- 작성: 로그인한 사용자만 글 쓰기
고령자 대상이라 글씨 크게, 버튼 크게. 한 화면에 너무 많은 정보 넣지 말 것.
```

## 5단계 · 인증 + 좋아요

```
Supabase Auth로 이메일 로그인을 붙여줘.
- 로그인 안 해도 글은 읽을 수 있게
- 글쓰기·좋아요는 로그인 필요
- 좋아요는 한 사람이 한 번만, 다시 누르면 취소
```

## 6단계 · 콘텐츠 채우기 (플랫폼 연결)

```
../../packages/shared/data 의 질환·약물 데이터를 참고해서,
고령자 건강정보 블로그 글 5개를 샘플로 작성해줘.
예: "고혈압이 있다면 국물을 줄이세요", "함께 먹으면 위험한 약 조합"
너무 의학적이지 않게, 쉬운 말로. 각 글 끝에 "참고용이며 의사 상담 권장" 문구.
```

## 7단계 · 배포

```
Vercel에 배포 준비해줘. 환경변수(Supabase 키)를 Vercel에 어떻게 넣는지 알려줘.
build 통과 확인 먼저.
```

---

## 주의

- `.env.local`과 Supabase **service_role key**는 절대 git·프런트엔드에 노출 금지.
  anon key만 프런트에서 쓰고, 나머지는 RLS로 보호하는 게 이 챕터의 요점.
- RLS 정책을 만든 뒤 실제로 "남의 글을 수정하려 하면 막히는지" 테스트해보세요.
  막히면 성공.
